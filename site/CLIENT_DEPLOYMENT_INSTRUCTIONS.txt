ASHPULSE INFRASTRUCTURE MONITOR - IIS DEPLOYMENT

This is a framework-dependent Windows x64 Release publish. Copy the CONTENTS of this folder into the IIS site's physical folder (for example, C:\inetpub\wwwroot\AshPulse). Keep web.config beside UniversalITMonitor.Web.exe.

For the detailed step-by-step Bengali implementation, IIS, SNMP, go-live, troubleshooting, and upgrade guide, see IMPLEMENTATION_GUIDE_BN.md in this package.

SERVER REQUIREMENTS
- Windows Server with IIS and the ASP.NET Core Hosting Bundle for .NET 10 (x64).
- Use a dedicated IIS application pool with .NET CLR set to No Managed Code, 64-bit enabled, and one worker process.
- Configure an HTTPS binding and DNS/firewall access for the client environment.

DEPLOY
1. Back up the current IIS application folder before replacing its files. Preserve the existing App_Data folder if the application has already been used; it contains application data.
2. Copy every published file and folder from this package into the IIS physical folder. Do not copy the source project or bin/obj folders.
3. Edit appsettings.json on the server and replace AllowedHosts "*" with the actual DNS name(s) used to access this application. Keep Storage:DataDirectory configured for App_Data unless the client has deliberately chosen another writable location.
4. Grant the application pool identity (IIS AppPool\<PoolName>) Modify permission to the application folder, including App_Data, so the application can create and update its local data and logs.
5. Start the application pool and browse to the site's HTTPS address. Complete the first-run administrator setup shown by the application. There is no preset admin password in this publish.
6. Confirm sign-in, device polling, alerts, and notification settings in the client environment.

NOTES
- The application creates its configured data folder when needed; preserve that folder during upgrades.
- Do not expose the application over plain HTTP on an untrusted network.
- This package includes Production IIS configuration in web.config. Do not change its ASP.NET Core handler settings unless required by the hosting environment.
- Back up appsettings.json and App_Data before applying future releases; reapply environment-specific settings after replacing publish files.
